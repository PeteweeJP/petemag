# SEO

## Titles and descriptions
- **Page title pattern:** `{Page title} — The Portfolio of Peter Magulak` (set in `src/layouts/BaseLayout.astro`)
- **Home title:** "Creative Director Peter Magulak" (`src/data/site.ts`)
- **Descriptions:** each case study's meta description is its first paragraph, trimmed to about 155 characters. To write one by hand, add `seoDescription:` to the frontmatter (140–160 characters naming the client, the work and the role). Pages without text get a generated fallback. Section pages use the summaries in `src/data/site.ts` → `sections`.
- **Share image:** a case study's first image that actually exists (else its tile image) is used as `og:image`. Pages with no image yet send no `og:image`, rather than a broken one.

## For AI agents and LLMs
- **`/llms.txt`:** a plain-text index of the site (who Pete is, contact, every page with a one-line summary), following the llmstxt.org convention. Generated from the content files by `src/lib/llms.ts`, so it never goes stale.
- **`/llms-full.txt`:** the full text of every case study, what each page shows, and the résumé, in one file.
- **Structured data (JSON-LD):** every page describes Pete as a `Person` (job, employer, LinkedIn). Case studies are `CreativeWork` with breadcrumbs, section pages are `CollectionPage` lists, and Home and Resume are `ProfilePage`. Code: `src/lib/schema.ts`. Test a live page at https://validator.schema.org.
- **Semantic HTML:** one `h1` per page, labeled navigation, real alt text on every image, and descriptive link names on tiles (e.g. "Paradise Pancakes Campaign (IHOP)").
- Crawlers (including AI agents) are allowed in `robots.txt`. To opt out of AI training crawlers later, add rules there (e.g. `User-agent: GPTBot` / `Disallow: /`) in `src/pages/robots.txt.ts`.

## Indexing
- `site.indexable` in `src/data/site.ts` is **false** during preview. Every page gets `noindex`, so the github.io copy doesn't compete with petemag.com.
- A sitemap is generated automatically (`sitemap-index.xml`), excluding the 404 page.
- `robots.txt` is generated by `src/pages/robots.txt.ts` so its sitemap link always matches the domain.
- The current Squarespace site blocks crawlers via robots rules (see audit §9). The new site shouldn't.

## URLs
Pages are flat and have no trailing slash, like Squarespace: `/paradise`, built as `paradise.html`. Internal links, canonical tags and the sitemap all use the same form, so nothing redirects. Old links with a trailing slash (`/paradise/`) reach the 404 page, which forwards them to `/paradise`.

Confirmed live URLs:

| Slug | Confirmed |
|---|---|
| `/comcast-business`, `/comcast-business-mobile`, `/ihop-ecommerce-website`, `/ihop-menu-photoshoot`, `/ihopar`, `/paradise`, `/expotv`, `/genvideo` | ✅ |
| All others | ❌ guessed. Check each against the live site and rename the content file if different, then set `slugVerified: true`. |

To find unverified ones: `grep -l "slugVerified: false" src/content/*/*.md`

If a slug has to change after launch, add a redirect in `astro.config.mjs` (`redirects: { '/old': '/new' }`).

## Domain cutover checklist
1. All slugs verified, all TODOs resolved (`grep -rn TODO src/`).
2. `astro.config.mjs`: `site: 'https://petemag.com'`, `base: '/'`.
3. `src/data/site.ts`: `indexable: true`.
4. Add `public/CNAME` containing `petemag.com`.
5. GitHub → Settings → Pages → Custom domain: `petemag.com`, enforce HTTPS.
6. DNS at the registrar: `A` records for `@` → 185.199.108.153, .109.153, .110.153, .111.153, and `CNAME` `www` → `peteweejp.github.io`.
7. Cancel Squarespace only after the new site is live and verified.
8. Submit the sitemap in Google Search Console.
